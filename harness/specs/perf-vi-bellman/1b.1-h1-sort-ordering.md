## Objective *(required)*

Run **exactly one** experiment — hypothesis **H1** from `benchmark/REPORT.md` § 7 — implement it, measure it alone
against the commit before it, and decide accept or reject. Accepted: kept as its own commit. Rejected: reverted, with
the code diff summarised in the `REPORT.md` entry. Either way the entry is written (rejected experiments stay recorded).
Measured against the head of `1a`.

*Measurement (Phase 0):* dynamic `Base.Order._by(by::Function, …)` is 67% of samples for the real model, 50% for
`product-imdp-sparse-n10000-nnz10-a4-dfa4`, 8% at k = 100; every column allocates 2 objects / 64 B. The cause is the
keyword call `sort!(Vp_workspace; rev = upper_bound, by = first, scratch = …)` in `src/bellman.jl` (sparse IMDP path,
and `sortperm!(…; rev = upper_bound, …)` on the dense path), where `rev` is a runtime `Bool`.

*Change:* build the ordering once per call with a concrete type (dispatch on `upper_bound`, e.g. `Val` or two methods,
`Base.Order.By(first)` / `ReverseOrdering`), call the positional `sort!(v, alg, order)` form with the preallocated
scratch, no keyword `NamedTuple`, no per-column `SubArray` allocation. The same stable ordering must result, so values
and strategies are identical.

*Scope:* the IMDP/product O-max sort. The factored O-max sort (`orthogonal_inner_bellman!`) is `4b.3`. If the natural
implementation is a shared helper that the factored path also uses, the factored O-max cases become target cases of this
experiment too, and the `4b.3` row in the Phase 4 plan is marked "done in 1b.1".

*Prediction:* 2–3× on k ≤ 10 cases and the real model, 1.1–1.3× at k = 100, zero steady-state allocations.

Adds or semantically changes a VI/Bellman algorithm: **no**. Every change computes the same result as the merge base
within the tolerances of `common.md` § Julia Behavior & Tests; anything else is raised as a Finding (`S-<n>`) and not
merged. Tier 1/2 interface changes: only additive keywords with defaults, documented; anything wider is an `I-<n>`
Finding (`common.md` § Interface Stability). Lean: if a Julia function cited by a Lean docstring is renamed, moved or
split, update the docstring in this run and keep `lake build` and `check_julia_refs.py` green.
Follow `common.md` § Context budget. Ops: push the commit(s) to `perf/phase-1` (same draft PR).
