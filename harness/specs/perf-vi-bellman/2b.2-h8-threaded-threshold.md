## Objective *(required)*

Run **exactly one** experiment — hypothesis **H8** from `benchmark/REPORT.md` § 7 — implement it, measure it alone
against the commit before it, and decide accept or reject. Accepted: kept as its own commit. Rejected: reverted, with
the code diff summarised in the `REPORT.md` entry. Either way the entry is written (rejected experiments stay recorded).
Measured against the head of `2b.1` (the best cut-off depends on the scheduler).

*Measurement (Phase 0):* `imdp-dense-n100-a4` 87% idle samples at t = 16 and 36 µs vs 19 µs at t = 8; the threaded path
allocates 82 objects / 7 KB per call. `construct_workspace` picks the threaded workspace when `num_sets > threshold`
(`threshold = 10`, `src/workspace.jl`).

*Change:* choose the threaded workspace by an estimate of work (columns × support size) instead of the number of sets,
with the cut-off set from a measured sweep over sizes and thread counts (`benchmark/results/2b.2-sweep.md` (committed summary of the local sweep JSON)).
**Interface:** `construct_workspace`'s `threshold` keyword is tier 2 — its meaning must not change. Add a new keyword with
a default (documented in the docstring, listed in the PR description), or raise an `I-<n>` Finding and stop.

*Prediction:* removes the 1.5–2× slowdown of small models at high thread counts; no change for large models.

Adds or semantically changes a VI/Bellman algorithm: **no**. Every change computes the same result as the merge base
within the tolerances of `common.md` § Julia Behavior & Tests; anything else is raised as a Finding (`S-<n>`) and not
merged. Tier 1/2 interface changes: only additive keywords with defaults, documented; anything wider is an `I-<n>`
Finding (`common.md` § Interface Stability). Lean: if a Julia function cited by a Lean docstring is renamed, moved or
split, update the docstring in this run and keep `lake build` and `check_julia_refs.py` green.
Follow `common.md` § Context budget. Ops: push the commit(s) to `perf/phase-2` (same draft PR).
