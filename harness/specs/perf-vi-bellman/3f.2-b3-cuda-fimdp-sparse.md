## Objective *(required)*

Fix Finding **B-3** from `benchmark/REPORT.md` § 8 in its own commit with a regression test
(`common.md` § Findings policy: allowed because the fix restores documented behaviour). This is a correctness fix, not
an optimization: no speed claim is made, but the benchmark suite must stay valid. It runs before the experiments of the
phase so that they are measured on the fixed code.

*Bug:* for a 2-variable fIMDP with 3 non-zeros per marginal column, `bellman` on CUDA returns all zeros
(max |CPU − CUDA| = 0.68; dense marginals agree to 2e-16), so RVI stops after 1 iteration (CPU: 667). One `solve` sample
of `fimdp-sparse-v3-d20-k5-a4-omax` also took 3 287 s. Find the cause in `ext/cuda/` (sparse marginal path of the
factored O-max kernel), fix it, and re-enable the sparse-marginal fIMDP cases in the CUDA suite with reference values
from this commit (Float64/Float32). If the hang has a separate cause, record it as its own Finding.

Adds or semantically changes a VI/Bellman algorithm: **no**. Every change computes the same result as the merge base
within the tolerances of `common.md` § Julia Behavior & Tests; anything else is raised as a Finding (`S-<n>`) and not
merged. Tier 1/2 interface changes: only additive keywords with defaults, documented; anything wider is an `I-<n>`
Finding (`common.md` § Interface Stability). Lean: if a Julia function cited by a Lean docstring is renamed, moved or
split, update the docstring in this run and keep `lake build` and `check_julia_refs.py` green.
Follow `common.md` § Context budget. Ops: push the commit to `perf/phase-3` (same draft PR).
