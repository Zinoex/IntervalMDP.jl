## Objective *(required)*

Run **exactly one** experiment — hypothesis **H7** from `benchmark/REPORT.md` § 7 — implement it, measure it alone
against the commit before it, and decide accept or reject. Accepted: kept as its own commit. Rejected: reverted, with
the code diff summarised in the `REPORT.md` entry. Either way the entry is written (rejected experiments stay recorded).
Measured against the head of `1b.1` (it builds on H1's ordering).

*Measurement (Phase 0):* 25% of samples in `setindex!` building the `(V[j], gap)` tuples for sparse k = 100 cases
(`profiles/imdp-sparse-n10000-nnz100-a4.md`, `imdp-sparse-n100000-nnz100-a1.md`).

*Change:* sort the support indices by a precomputed global rank of `V` (one `sortperm` per call, as the dense path does)
instead of copying values into tuples; optionally a partial selection up to the budget. Ties must break exactly as on the
merge base (stable order among equal values by support position), so values and strategies stay identical; if that is
not possible, stop and raise an `S-<n>` Finding.

*Risk:* the per-call `sortperm` of `V` is O(n log n) and may regress the k = 10 cases; they are regression-check cases.

*Prediction:* 1.2–1.5× for k = 100.

Adds or semantically changes a VI/Bellman algorithm: **no**. Every change computes the same result as the merge base
within the tolerances of `common.md` § Julia Behavior & Tests; anything else is raised as a Finding (`S-<n>`) and not
merged. Tier 1/2 interface changes: only additive keywords with defaults, documented; anything wider is an `I-<n>`
Finding (`common.md` § Interface Stability). Lean: if a Julia function cited by a Lean docstring is renamed, moved or
split, update the docstring in this run and keep `lake build` and `check_julia_refs.py` green.
Follow `common.md` § Context budget. Ops: push the commit(s) to `perf/phase-1` (same draft PR).
