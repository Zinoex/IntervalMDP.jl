## Objective *(required)*

Run **exactly one** experiment — hypothesis **H2** from `benchmark/REPORT.md` § 7 — implement it, measure it alone
against the commit before it, and decide accept or reject. Accepted: kept as its own commit. Rejected: reverted, with
the code diff summarised in the `REPORT.md` entry. Either way the entry is written (rejected experiments stay recorded).
Measured against the head of `2a`.

*Measurement (Phase 0):* t = 16 slower than t = 14 for 3 of 4 strong-scaling cases (dense n4000 a1 9.75 vs 7.75 ms;
sparse k10 9.78 vs 3.60 ms); efficiency 47–58% at t = 16 vs 76–96% at t ≤ 6; 59–78% idle samples in the t = 16
profiles. `@threadstid` (`src/threading.jl`) splits the range into equal static chunks, so the LP-E cores finish last.

*Change:* dynamic chunked scheduling (e.g. an atomic chunk counter, or `:greedy`) as a new threaded method selected by
dispatch (new workspace type or `_bellman_helper!` method), not as a branch in the hot loop. The chunk size is a named
constant set from a measured sweep (e.g. 32–512 states) kept in `benchmark/results/2b.1-sweep.md` (committed summary of the local sweep JSON). Per-state
results are independent of the schedule, so values and strategies must be **identical** (`==`).

*Prediction:* t = 16 throughput ≥ t = 14; 1.2–2.5× at t = 16; no change at t ≤ 6.

Adds or semantically changes a VI/Bellman algorithm: **no**. Every change computes the same result as the merge base
within the tolerances of `common.md` § Julia Behavior & Tests; anything else is raised as a Finding (`S-<n>`) and not
merged. Tier 1/2 interface changes: only additive keywords with defaults, documented; anything wider is an `I-<n>`
Finding (`common.md` § Interface Stability). Lean: if a Julia function cited by a Lean docstring is renamed, moved or
split, update the docstring in this run and keep `lake build` and `check_julia_refs.py` green.
Follow `common.md` § Context budget. Ops: push the commit(s) to `perf/phase-2` (same draft PR).

## Performance Evidence *(required)*

Interleaved A/B (A = the commit before this experiment, B = the candidate; A B A B …, ≥ 3 rounds each,
separate Julia processes) on CPU, 4, 8 and 16 threads for the target cases, verdict per `common.md` § Evidence Protocol
→ Statistics (speedup ≥ 5% in every round or Mann–Whitney p < 0.01; regression > 3%). Regression check on CPU, 1 thread
